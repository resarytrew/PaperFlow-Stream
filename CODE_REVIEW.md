# PaperFlow Stream — Code Review и предложения по расширению

> Объект: backend FastAPI (`/backend/app`), ветка `arena/019f9863-paperflow-stream`.
> Сфера: потоковое сканирование письменных работ учеников через браузерную камеру +
> локальное распознавание рукописного текста (OCR) + кабинет проверки учителя + экспорт.
> Язык исходников: Python 3.11, русскоязычные сообщения UI.

---

## 1. Общая оценка архитектуры

Проект написан **на удивление аккуратно** для MVP. Хорошие стороны, которые стоит сохранить:

- **Чёткое разделение слоёв**: `cv/` (детекция/геометрия/нормализация/QR), `ocr/`
  (абстракция провайдера + локальный инференс), `services/` (оркестрация сканирования,
  очередь OCR, экспорт, хранилище, настройки), `api/` (только HTTP/WS-транспорт).
- **Чистая конечный автомат** `ScanStateMachine` — без I/O, полностью юнит-тестируем
  (`cv/state_machine.py`). Это образцовый паттерн.
- **Честность про HTR**: провайдер явно предупреждает, что встроенная модель плохо читает
  русский рукописный текст, и слабые результаты маршрутизируются на ручную проверку, а не
  выдаются за истину. Система **принципиально не выставляет оценки** (только ключевые слова) —
  верное этическое решение для школьного контекста.
- **Приватность по умолчанию**: локальный инференс, удаление изображений вместе с сессией,
  отсутствие PII в технических логах, защита от path-traversal в `storage.absolute()`,
  глобальный обработчик ошибок без утечки стека в браузер.
- **Офлайн-воспроизведение**: `cv/synthetic.py` + `testing/replay.py` позволяют гонять
  пайплайн без камеры (12 сценариев). Отличная база для регрессионных тестов.
- **Устойчивость**: «один плохой кадр не убивает поток» — обёртки try/except вокруг analyze/
  process и вокруг каждого worker'а OCR.
- **Конфиг слоями**: код → БД (`app_settings`) → UI (раздел Settings), с валидацией.

Ниже — конкретные дефекты и точечные улучшения, отсортированные по влиянию на работу учителя.

## 2. Дефекты (баги), влияющие на работу учителя

### 2.1 🔴 Дубликаты определяются глобально, а не в рамках сессии — `services/scan_service.py:460`
```python
existing = db.execute(
    select(ScannedSheet)
    .where(
        ScannedSheet.sheet_uid == sheet_uid,
        ScannedSheet.scan_status != ScanStatus.deleted.value,
    )
    .order_by(ScannedSheet.id)
).scalars().first()
```
`sheet_uid` детерминирован (`build_sheet_uid(student, task, index)`). Если учитель **второй раз
сканирует тот же класс и то же задание** (пересдача, новая сессия), то при проверке дублей
находится лист из *предыдущей* сессии → **все 30 работ помечаются «дубликат»**. То же самое в
`reprocess_sheet` (`api/routes_sessions.py`).

**Исправление:** ограничить поиск текущей сессией (или сделать опцией):
```python
.where(
    ScannedSheet.sheet_uid == sheet_uid,
    ScannedSheet.session_id == session.id,           # <-- добавить
    ScannedSheet.scan_status != ScanStatus.deleted.value,
)
```
При этом «истинные» дубли внутри одной сессии (случайно прогнали лист дважды) продолжат
ловиться. Для пересдач между сессиями можно добавить флаг `allow_cross_session_duplicate` в
настройках сессии.

### 2.2 🔴 Мёртвый код / незаконченная логика в `complete_session` — `api/routes_sessions.py:181-186`
```python
target = SessionStatus.review.value if stats.pending_ocr or stats.needs_review else SessionStatus.completed.value
session = _set_status(db, session, target)
if target == SessionStatus.review.value:
    session = _set_status(db, session, SessionStatus.completed.value) if False else session  # <-- мусор
```
Ветка `if False` ничего не делает. В итоге завершение сессии с нераспознанными листами
оставляет её в статусе `review`, а не `completed`. Статус `review` по модели — промежуточный,
и учитель увидит «невыполненную» сессию. Сделайте логику явной:
```python
# Завершение = completed. Очередь проверки сама покажет, что ещё нужно разобрать.
session = _set_status(db, session, SessionStatus.completed.value)
```
(Если нужно именно «на проверку» — введите отдельный статус и используйте его осмысленно,
без мёртвого `if False`.)

### 2.3 🟠 `/api/health` и `/ocr/status` загружают тяжёлый OCR-движок на каждый вызов — `main.py:91`, `api/routes_review.py:232`, `ocr/providers.py:385`
`LocalHandwritingProvider().describe()` обращается к `.available`, который вызывает
`_ensure_engine()` → загружает RapidOCR (ONNX, сотни МБ и ~секунды). Проблемы:
1. Мониторинговые системы бьют `/health` часто → каждый раз грузится модель.
2. `available_providers()` создаёт **новый** экземпляр `LocalHandwritingProvider()` при каждом
   вызове, и движок не кэшируется между вызовами → **утечка памяти** (несколько копий RapidOCR
   в RAM), если страница настроек опрашивает `/ocr/status`.

**Исправление:** сделать провайдеры синглтонами и не грузить движок в статусных эндпоинтах.
```python
# ocr/providers.py
def available_providers() -> list[dict]:
    return [get_provider("local").describe(),
            get_provider("mock").describe(),
            get_provider("cloud").describe()]

# main.py / health: не грузить движок, только задекларировать
"ocr": {"queue": ocr_queue.snapshot(), "local": {"provider": "local", "available": ocr_queue.is_engine_loaded()}}
```
И добавить глобальный синглтон `LocalHandwritingProvider` (аналогично `get_provider`), чтобы
движок грузился ровно один раз.

### 2.4 🟠 QR-читаемость считается на **каждом** кадре — `services/scan_service.py` (`analyse_frame`)
```python
qr_readability=qr_readability_score(warped_small, runtime.qr_region),
```
`qr_readability_score` делает `read_qr(... enhance=False)` (декод QR) для каждого анализируемого
кадра (~12 кадров/сек). Это лишняя нагрузка на CPU и может снижать FPS на слабых ноутбуках
учителя.

**Исправление:** считать QR-читаемость только в окне сбора кандидатов (или раз в N кадров), либо
использовать лёгкий прокси (локальный контраст finder-паттерна) без полного декода.

### 2.5 🟡 `sequence_number` считается по всем листам, включая удалённые — `services/scan_service.py`
```python
sequence = int(db.execute(select(func.count(ScannedSheet.id))
    .where(ScannedSheet.session_id == session.id)).scalar_one() or 0) + 1
```
Удалённые листы не вычитаются → номера `1,2,4,5…` с пропусками. Не критично, но путает при
экспорте/печати «Лист N». Либо исключать `deleted`, либо не использовать `sequence_number` как
видимый порядковый номер (он уже отсортирован по id).

### 2.6 🟡 `diagnostics_recording_enabled` объявлен, но нигде не применяется — `config.py` / `api/routes_scan.py`
В `PrivacyConfig` есть флаг `diagnostics_recording_enabled`, но `export_diagnostics` и запись
`runtime.diagnostic_frames` управляются только клиентом через сообщение `diagnostics`. Значит
администратор/учитель не может централизованно запретить запись кадров (потенциально —
приватность). Либо удалить флаг, либо проверять его в `export_diagnostics` и при старте записи.

## 3. Производительность и ресурсы (для плавной работы на школьном ноутбуке)

- **Передача кадров как base64 data-URL** (`decode_data_url`/`encode_data_url`) по WebSocket.
  Для 1280×720 JPEG q0.72 это ~150–250 КБ base64 на кадр, ×12 fps. Переход на **бинарные
  WebSocket-кадры** (`await websocket.send_bytes(...)` / `await websocket.receive_bytes()`)
  срежет CPU на кодирование/декодирование и трафик на ~30%. См. `api/routes_scan.py` и `storage.py`.
- **Кандидаты хранят полноразмерный кадр** `frame.copy()` (до `max_candidates=8` штук по ~2 МБ =
  до 16 МБ на сессию в RAM). Можно хранить только уменьшенную копию для оверлея и полный — только
  у лучшего кандидата после выбора.
- **N+1 в `serialize_session`**: `session_stats()` делает ~6 запросов и вызывается для *каждой*
  сессии в `list_sessions`. При десятках/сотнях сессий — батч-агрегация одним запросом.
- **`dashboard`**: `today_sessions` берёт `midnight - timedelta(days=1)`, хотя в комментарии
  «today's sessions» — логика и комментарий расходятся (берутся сессии за последние ~2 дня).

## 5. Расширение функционала для максимального удобства учителя
*(отсортировано по «цена/польза» для реального класса)*

### 5.1 🥇 Выставление оценки / баллов (самое востребованное)
Сейчас система **умышленно не оценивает**, но у учителя нет места записать отметку.
Добавить в `ReviewDecision`: `score: float | None`, `max_score`, `grading_scale` (в `Task`),
и колонку в XLSX/CSV. Это закрывает главный «недостающий» сценарий: сканировал → проверил →
**выставил оценку → экспортировал в журнал**.

### 5.2 🥇 Импорт списка учеников из CSV/XLSX
`/students/bulk` принимает JSON. Учителя работают в Excel/CSV — добавить эндпоинт
`POST /students/import-csv` (или парсер в `bulk_create_students`) с маппингом
`Фамилия;Имя;ID`. Без этого набор 30 учеников руками — боль.

### 5.3 🥇 Массовые действия в очереди проверки
Сейчас решение принимается **по одному листу**. Добавить:
- «Принять все с high_confidence» (bulk accept),
- «Отправить все с needs_review/low на повторное сканирование»,
- мультивыбор + общая кнопка.
Эндпоинт `POST /sessions/{id}/review/bulk` с массивом `sheet_ids` и действием.

### 5.4 🥈 Поиск и фильтры в проверке
Вкладки (`all/high_confidence/needs_review/…`) есть, но нет поиска по **фамилии ученика** и по
**тексту распознанного ответа**. Добавить `?q=` в `list_review_sheets` (по `student.display_name`
и `recognition.recognized_text`). Для учителя это критично при 100+ работах.

### 5.5 🥈 Несколько зон ответа / длинный ответ
Шаблоны поддерживают `answer_regions: list`, но `process_best_candidate` берёт только
`runtime.answer_regions[0]`. Поддержать N зон (страница 2, черновик) → OCR по каждой и
конкатенация. Плюс «многостраничная работа»: одна `ScannedSheet` = несколько отсканированных
листов (связь 1:N).

### 5.6 🥈 Горячие клавиши и автосохранение в кабинете проверки
`Enter` — принять, `F2` — исправить, `R` — повторное сканирование, `Del` — удалить.
(Фронт, но backend уже готов: `submit_review`/`blank-override`/`delete_sheet`.)

### 5.7 🥈 Отмена последнего скана («Undo»)
Быстрая кнопка «удалить последний принятый лист» текущей сессии (по `sequence_number` desc).
Сейчас удаление — только по id через отдельный экран.

### 5.8 🥉 Рубрика/критии оценки на задании
`Task` расширить полем `rubric: list[str]`; в проверке учитель отмечает выполненные критерии,
итоговый балл считается автоматически. Дружелюбнее, чем свободная оценка.

### 5.9 🥉 Аналитика по классу/заданию
Дашборд показывает счётчики, но полезно: распределение баллов по заданию, % не справившихся,
сравнение классов. Без PII — только агрегаты, видны учителю. Готовый `export_service` легко
расширить сводным листом.

### 5.10 🥉 Повторное распознавание выделенной области
В кабинете проверки учитель выделяет прямоугольник на `answer_crop` → backend режет и
перезапускает OCR только для этого региона (`POST /sheets/{id}/recognize-region`). Точечно
поднимает качество на слабых местах.

### 5.11 🥉 Режим «родитель/ученик» (только чтение, приватность)
Сгенерировать временную read-only ссылку на результат конкретного ученика (без доступа к
остальным). Это снимает вопрос «как отдать работу обратно», не нарушая приватность остальных.

### 5.12 🥉 Шаблоны сессий и пресеты камеры
Сохранять связку «класс + задание + профиль калибровки + настройки качества» как пресет, чтобы
следующий урок запускался в два клика, а не через мастер калибровки.

## 6. Безопасность / приватность (на будущее)

- **Нет аутентификации**. Для локального класса ок, но для кабинета информатики с общим сервером
  нужен хотя бы простой логин/пароль (или OAuth школьного контура). Все эндпоинты сейчас открыты.
- `CORS allow_credentials=True` + фиксированные origin'ы — ок. Не выставлять `*` в проде.
- `CloudHandwritingProvider` отключён по умолчанию и требует явного согласия — правильно.
- Ретеншн файлов реализован (`/maintenance/retention`), но не запускается по расписанию.
  Добавить фоновую задачу (APScheduler) или cron-вызов CLI `python -m app.cli retention`.
